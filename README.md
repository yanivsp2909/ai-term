# AI Term

AI Term is the `ai` command: one terminal homepage for running AI coding agents side by side. It starts Claude Code and Codex (and, since Part B, Cursor, Gemini CLI and Copilot CLI) on your own logins, untouched, and its own agent on any API key you save. Each agent gets its own git worktree, so they can't step on each other or on your checkout. A background service keeps them running when you close the terminal. The homepage lists every agent with a live preview of its screen, your API spend and what the machine is doing, and you type what you want built at the bottom. When an agent is done you read its diff, test it, review it, and merge it, each step only when you ask. It's Yaniv's personal and learning project: macOS first, Linux and Windows since v0.8.

**Status: 1.0.0** (2026-10-18). Every version up to 1.0 passed its release gate; [CHANGELOG.md](CHANGELOG.md) lists what each one added. Live checks that need your own logins, Tailscale or REA are listed in PROGRESS.md.

## Install

### From source (macOS, Linux, Windows)
You need Node 22 or newer and git 2.41 or newer (Debian 12 and Ubuntu 22.04 ship older ones). For Claude Code or Codex on your own login, install and log in to those CLIs first. Cursor, Gemini CLI and Copilot CLI sign in through their own login inside AI Term (`/login`); AI Term never installs a CLI, it shows the install command instead.
```sh
git clone <this repository> ai-term && cd ai-term
npm install
npm run build
npm link          # puts `ai` on your PATH (or run: node dist/cli/index.js)
ai
```
`npm run dev` runs `ai` from source without building. `npm run build:notifier` builds the macOS notification helper (needs Xcode Command Line Tools); without it AI Term just doesn't notify.

### The Mac app and the `ai` link
`npm run app:dist` builds **AI Term.app** and a zip (`build/desktop/dist/`). Drag the app into Applications. It's ad-hoc signed, not notarized, so the first time right-click it → Open → Open (or Privacy & Security → Open Anyway). The app needs no Node: it runs `ai` and its daemon on its bundled runtime.

In the app, App menu → **Install `ai` command…** shows exactly what it makes: one link, `~/.local/bin/ai`, to the app's own `ai`. No sudo and no shell profile changes. If `~/.local/bin` isn't on your PATH, add it, and `ai` works in any terminal.

### Linux
- `sudo apt install bubblewrap` (or your distro's package) for the sandboxes. Without it, tests ask every time and AI Term's agent is Ask only.
- A Secret Service keyring (GNOME Keyring or KWallet) for API keys. AI Term never stores a key in a file, so without one, key features say so and refuse.
- `notify-send` for notifications, and `wl-copy`, `xclip` or `xsel` for the clipboard.
- `npm run app:dist` on Linux builds an AppImage and a .deb, unsigned. The desktop keys are Ctrl+Shift where macOS uses ⌘.
- Everything else, and what differs: [Linux details](#linux-details-v081).

### Windows
- Git for Windows: AI Term's agent's bash and every git call use it.
- There's no sandbox AI Term can use on Windows, so tests ask every time and AI Term's agent is Ask only.
- `npm run app:dist` on Windows builds an NSIS installer. It's unsigned, so SmartScreen warns "Windows protected your PC" the first time: More info → Run anyway.
- Everything else, and what differs: [Windows details](#windows-details-v082).

## First run
1. Run `ai`. The background service starts by itself. `ai doctor` checks Node, the service, the CLIs and their logins, the sandbox, the credential store, gh and the notifier.
2. Nothing logged in yet? The login popup opens. Pick Claude or ChatGPT to use that CLI's own login, or save an API key. Keys go to the OS keychain and never to a file. `/login` opens it again later.
3. `/cd` picks the project folder. Type what you want built and press ⏎. The start box shows the engine, model, folder, mode and worktree; ⏎ starts it.
4. With the command bar empty, ⏎ opens the selected agent full screen. Ctrl+E brings you back home, and the agent keeps working.
5. When it's done: `d` shows its diff, `/test` runs your tests, `/review` gets a second opinion from another model, and `/merge` merges its branch. Each one asks first.

`/help` lists every command and key, and so does the [list below](#commands-and-keys). The [user guide](docs/user-guide.md) explains each area, and the [changelog](CHANGELOG.md) shows what changed in each version.

## Security model, in plain words
- **Your keys:** API keys live only in the OS keychain: the macOS Keychain, Secret Service on Linux, Credential Manager on Windows. Only the background service reads one, right before it starts an agent that needs it, and puts it in that agent's environment alone. The homepage only ever knows a key's last 4 characters. Claude Code and Codex on your own login get none of your keys, so they can't quietly bill one. AI Term never reads, copies or edits those CLIs' own logins (`~/.claude`, `~/.codex`).
- **Ask (the default):** agents ask before they act. Claude Code and Codex use their own prompts. AI Term's agent shows every write, edit and command exactly as it will run, and waits for y.
- **Don't ask:** it's per agent, chosen when you start one, and never a default. The card shows it with `!`. What an agent can still do then depends on its engine:
  - **Claude Code** runs with its permission prompts off and no sandbox from AI Term. It can do anything your user account can, anywhere in your home, so use it only on work you'd let run unattended.
  - **Codex** stays in its own workspace-write sandbox: it writes in its folder and a temp folder.
  - **AI Term's agent** runs every command in a sandbox (sandbox-exec on macOS, bubblewrap on Linux; on Windows it's Ask only). Its commands never see your API keys or AI Term's own folder. It can't change shell startup files, login items, `~/.ssh`, git's global settings, or Claude Code's and Codex's settings.
  - **What it can still do in your home:** with its prompts off, AI Term's agent can still read your home, `~/.ssh` included (it can't change it), write anywhere else in your home, use the network, and install tools in `~/.local/bin` or `~/bin`. A tool placed there runs as you, outside any sandbox, the next time you call it.
- **Agent code you run:** tests (`/test`, auto-test) and dev servers (`/dev`) run the agent's code, with no keys in their env.
  - **Tests** run in a sandbox (macOS and Linux) that writes only in the worktree and a temp folder and has no network.
  - **Dev servers** are sandboxed on macOS only, where they listen on their own 127.0.0.1 port and nothing else. On Linux and Windows they run as you, after you type a capital `Y` each time.
  - **No sandbox:** wherever a sandbox can't start, AI Term asks you each time and says why.
- **Your checkout:** agents work in their own worktrees. `/merge` touches your checkout only when it's clean, after you've seen and accepted exactly what it will do and a secret scan has passed. Worktrees with unsaved work are never deleted without your word.
- **The background service:** it's reachable only by your user. On macOS and Linux that's a socket in `~/.ai-term` (folder 0700, socket 0600); on Windows a named pipe with a token only your account can read. It refuses to start if that folder is a link or belongs to someone else.
- **Things that spend tokens on their own** (auto-review, the queue, handoffs, diagnostics) are off until you turn them on in `/settings`. Anything that spends tokens shows its estimate and asks first.

## Commands and keys

Run `node dist/cli/index.js` after `npm run build`, or `npm run dev` from source. If the `ai` binary is installed, the same arguments work with `ai`.

Unzip the desktop distribution and drag **AI Term.app** into Applications. No Node installation is needed: the bundled Electron runtime runs `ai` and its daemon. The app is ad-hoc signed without notarization; on first launch right-click → Open and confirm Open. If macOS still blocks it, use Privacy & Security → Open Anyway. Closing the app keeps agents running. A compatible existing dev daemon is reused; protocol mismatch is reported in one line and never stops it automatically.

The packaged window starts in your home folder; use `/cd` to choose a project. App menu → **Install `ai` command…** shows exactly what it will create: `~/.local/bin/ai` pointing to this app's `Contents/MacOS/ai`. No sudo, shell profile changes or overwriting foreign entries; symlinked `.local`/`bin` folders are refused. Add `~/.local/bin` to your Terminal PATH if needed, then `ai` works without Node and accepts the arguments below. **Uninstall `ai` command** removes only the exact symlink pointing at this app. Uninstall before moving the app; a link pointing elsewhere is refused.

For source development, install Node ≥22, `npm install`, then `npm exec -- install-electron --no` once (Electron 44's installer) and `npm run app:dev`. Development loads local production bundles; rerun after edits. `npm run build` keeps the plain system-Node CLI working. Packaging uses isolated staging without rebuilding source dependencies; distribution builds require Xcode Command Line Tools for the notifier/native launchers.

Other terminal keys go straight to `ai`. Web links open only http/https in your default browser. The hidden title bar keeps inset traffic lights above the terminal; solid colors follow macOS live, including the TUI's palette after a new OSC 11 probe. The app inherits its launcher environment, matching current CLI startup; it does not read login files, fetch keys or reconstruct a login-shell environment. Desktop controls are authenticated with a per-launch token consumed before child-environment inheritance. They cannot carry agent text or approve a prompt; pasted and agent-printed controls are inert. Plain `ai` ignores these sequences.

The earlier app/Terminal.app physical typing comparison remains unmeasured, and the previous native step's historical 1.20 ms gate is recorded in PROGRESS.md. This packaging step uses a fresh same-session A/B against dev `11362d1`, gating only on packaged minus dev p95 ≤0.30 ms at 151×37 cells. Neither method measures physical paint or proves Terminal.app parity.

Removing worktrees (v0.3.2). AI Term keeps its own record of every worktree it creates, with the repo and the branch and commit it started from; the record outlives the agent. `x` removes the agent's list record, then asks once about its worktree:
- **Nothing would be lost:** `remove worktree and branch ai/<slug>? k keep · d delete`. Keep is the default: `k`, Esc and Enter keep. `d` runs `git worktree remove` then `git branch -d`, never forced, so git refuses by itself if anything changed.
- **Something would be lost:** the question lists it plainly: changed files (modified, staged, deleted), untracked files, and commits on `ai/<slug>` that aren't in the branch it was made from (merged work counts as safe). To delete anyway, type the branch name and press Enter. `k` or Enter on an empty field, or Esc, keeps it. One keypress never deletes work, and a paste never fills the name. Only then does AI Term force the remove and use `-D`, and only if nothing changed since you saw the list.
- Changed files include edits hidden from `git status` by `assume-unchanged` or `skip-worktree` flags, and any submodule folder that holds something (AI Term never runs git inside a submodule, so whatever is in it counts as work that would go). Untracked folders that are git repositories are called out, since their history goes too.
- Ignored files (`node_modules`, `.env`) go with any delete. They aren't counted as loss, but the question says how many there are; an ignored folder counts once. Only rules from a `.gitignore` committed in the repo count: files hidden by `.git/info/exclude`, a repo `core.excludesFile` or an uncommitted `.gitignore` count as untracked.
- The question also notes when a folder was already deleted by hand, when the base branch is gone (commits are then counted from where the agent started), and, for agents started before v0.3.2, that the base wasn't recorded and your checkout's current branch is used instead.

AI Term refuses, with a fixed reason and without touching anything:
- a path it has no record of
- a path outside `~/.ai-term/worktrees`, or one with a symlink in it
- a record pointing at a main checkout, or a repo that doesn't match the worktree's folder
- a worktree git doesn't list, a locked worktree, or one no longer on its own `ai/<slug>` branch (for example renamed)
- a branch checked out somewhere else
- a running or waiting agent: stop it first

If a step fails, it stops and says which step (`Worktree remove failed; branch kept` or `Worktree removed; branch delete failed`). It never deletes files itself and never touches another worktree or branch. `/clean` only removes list records and says how many worktrees it kept. `/worktrees` lists them all for later; folders in `~/.ai-term/worktrees` that no record claims (from agents removed before v0.3.2) appear as `✗ Not in AI Term's record` and are never deleted by AI Term. Remove those yourself with `git worktree remove` if you don't need them.

## Engines, usage and logins
`ai` starts Claude Code and Codex on their own logins, and AI Term's own agent on any saved API key (see below). `/login` connects an account or saves a key in the OS keychain (macOS Keychain, Secret Service on Linux, Credential Manager on Windows); `/settings` lists masked key metadata, tests Foundry deployments, imports selected keys from an env file without modifying it, and edits defaults/theme. This Mac updates once per second. Usage shows estimated API-key spend and tokens for today, this week and this month; subscriptions are excluded from those totals. Each agent's own total since it started (cost per task, v0.6.1) shows on its card and in `/usage`: dollars for API keys, tokens for subscriptions. `b` sets daily, weekly and monthly USD budgets, which hold across agents (a key session stops before a request crosses one); `/settings` offers Foundry deployment price overrides.

The card, preview, bar, splits, notifications, `c` and Usage work as for the CLIs.

- **Keys:** only in the agent's own environment, never in argv, a file, a log or the protocol. Each goes only to its own host in its own header: Foundry to the endpoint bound to the key in the Keychain (`api-key`), Anthropic to api.anthropic.com (`x-api-key`), OpenAI to api.openai.com (bearer); xAI api.x.ai, Moonshot api.moonshot.ai, Z.ai api.z.ai, OpenRouter openrouter.ai (bearer); Vertex aiplatform.googleapis.com (`x-goog-api-key`); Bedrock the runtime host of the region bound to the key in the Keychain (bearer API key, never AWS credentials from your environment); Ollama only `http://127.0.0.1:<port>`, with no key. Redirects are refused; provider error text is never shown.
- **Tools:** read, write, edit, bash, search (ripgrep when installed, else plain text). File tools stay inside the agent's folder (its worktree): `..`, absolute paths elsewhere and symlinks that lead out are refused. bash runs `/bin/sh -c <command>` in the folder with a 2-minute default limit (10 at most), 64 KB of output per stream, no stdin, and a minimal environment with no API keys and nothing of AI Term's. The agent's own key and AI Term's credentials never sit in its process environment (a 0600 file it reads and deletes at start carries them). On macOS every bash command runs in a sandbox that otherwise lets it do what you could, but can't read or write `~/.ai-term` (settings, budgets, prices, other agents' worktrees; its own worktree stays open) or connect to AI Term's sockets, can't attach to or look into your other processes (where keys live in memory), and can't write the repository's `.git/hooks` or `.git/config` (code there would run at your next commit), so a hijacked agent can't change your prices or budgets or talk to AI Term as you. `ps` can't run inside the sandbox (it is a setuid program); `pgrep` and `pkill` work. It also can't write the places that would run later outside the sandbox (B29): your shell startup files (`~/.zshrc`, `~/.zshenv`, `~/.zprofile`, `~/.zlogin`, `~/.bashrc`, `~/.bash_profile`, `~/.profile` and the like, also in `$ZDOTDIR` and at a link's target), `~/.config/fish`, `~/Library/LaunchAgents`, `~/.ssh`, `~/.gitconfig`, `~/.config/git`, `~/.claude`, `~/.claude.json` and `~/.codex` (nor rename or replace `~/.config` or `~/Library`, which hold some of them); such a refusal ends the tool's output with `✗ blocked by sandbox: ~/<path>` and why. It also can't rename a folder above any of those places, a dotfile link's target, the repository's `.git` or AI Term's folder, so they can't be swapped out (v0.8 gate). `$ZDOTDIR` and `$XDG_CONFIG_HOME` are followed: zsh's startup files there and git, fish, autostart and systemd config are protected too. It can still write anything else of yours (in Don't ask without asking). Linux has its own sandbox (below); on Windows, and wherever no sandbox can start, bash runs as you in Ask, saying so with each result (`(ran without a sandbox: …)`), and Don't ask is off.
- **Ask (default):** every write, edit and bash shows exactly what will run (the command, or the path and every changed line; escape sequences and invisible characters show as `␛` and `<U+…>` in every approval, job confirmation and MCP prompt) and waits for `y` or `n`. An approval taller than the screen pages: Space shows the next page, and `y` works only on the last one. Commands over 16 KB, and writes over a file larger than 1 MB, are refused. Reads and searches never ask. Don't ask is per session only (red `!`), never a saved default.
- **Instructions:** the folder's `AGENTS.md`, then `CLAUDE.md` with its `@file` import lines, go into the system prompt (inside the folder only, 64 KB per file).
- **Cost:** after each turn, one line with the provider's own counts and the exact price: `turn · 12.3k in · 4.0k cached · 812 out · 310 reasoning · $0.0123 · run …`. Priced like Usage (D45 list prices; a Foundry deployment uses its price override, else the model you marked it as in `/settings` → `m`, else its own name).
- **Limits (D49, D53):** before every request the agent works out what is left of the run's spend cap and of your daily, weekly and monthly budgets, takes off the request's input (an ASCII character as a third of a token, any other character as a whole one) and sends the largest output allowance whose worst case fits, never above the model's own limit (32k at most; 16k when the catalog doesn't know it). Reasoning counts as output inside that allowance. A request cut off by Esc or Ctrl+K, one that fails after the provider started answering, and one the provider sent no usage for count their worst case; usage that never reached AI Term keeps counting in the run. **Across agents (v0.6.1, B25):** before each request the agent asks the background service to hold that worst case; it is granted only if every budget still fits counting every other agent's held requests, so two agents near one budget can't cross it together. Nothing is sent without a grant (a restarted or unreachable service pauses the agent). A held request is released when its usage arrives, or counted at its worst case (it shows in Usage) when it never will: cut off, failed, no usage, the agent exited, 20 minutes passed, or the service restarted. It pauses and asks, before anything is sent, when what is left fits under 1,000 output tokens (a budget: raise it with `b` on the homepage, then ⏎ checks again; the spend cap: ⏎ allows as much again), when the run reaches its turn cap (a turn is one request to the model), when no price is known for the model while any limit is set, or when AI Term doesn't answer. **No price known (B28):** with a daily, weekly or monthly budget the agent waits for a price (there is no way to run outside a budget): `p` sets your price for that model right there (any provider but Anthropic and OpenAI, which always use the catalog; input / output, and optionally cache read, USD per 1M; prefilled from the catalog's closest model when there is one, labeled `guess, check it`; every number must be typed, so $0 is only ever yours), `m` (a Foundry deployment) marks which catalog model it is (type to narrow, ↑↓, ⏎), ⏎ checks again (say after `/settings` p), Esc stops. Saving either checks again and goes on. With only this run's spend cap, ⏎ goes on for that model this run with the model's own allowance. The agent can only add a price for its own model while it has none; changing a price is yours, in `/settings` p. A card running on a price you typed says `price: yours`. Ollama models are $0 and never pause on price. A deployment whose real output limit is under 16k refuses until you mark its catalog model in `/settings` → `m`. Esc stops. Defaults: 100 turns and $5.00 per run (`/settings` → `c`); `/caps` changes one run.
- **Kill switch:** Ctrl+K stops the request and kills every running command's whole process group at once (no grace period); queued messages are dropped. `s` on the homepage does the same and stops the agent.
- **Context:** ctx % on the card and the bar, from the model's context window in the catalog. At 85% the agent and the card show `context 85% · /compact or /clear` once per crossing (a CLI card says `/compact`); `/settings` → `k` turns it off. The catalog shipped before v0.4.2 has no context windows: refresh it (manual checks in PROGRESS.md) and ctx % appears.
- `/resume` isn't available yet; `/retry` starts it fresh.

`/skills` and `/agents` work on the homepage and inside AI Term's agent. They open the same popup, starting on the corresponding tab. The homepage uses the next-agent folder selected by `/cd`; inside the agent it uses that agent's current folder. Official CLIs keep their own in-session commands.

Each row shows the name, one-line description, source (Claude, Codex, shared, this project), on/off and estimated tokens per request. The header and agent banner show the enabled manifest's total. Built-in slash commands always win.

## MCP servers (v0.4.4)

`/mcp` lists AI Term's own servers and the current folder's `.mcp.json` entries in the MCP tab of the same extensions popup. `/mcp add` opens the form on either terminal surface: name, stdio/http, one executable plus a JSON argv array or an exact URL, then comma-separated env/header names and masked values. Typed Enter reviews and saves the exact command/URL. `/mcp remove <name>` removes an AI Term entry. Project entries are managed in the project's file; AI Term never edits it or the CLIs' files. `~/.claude.json` and `~/.codex/config.toml` stay denied.

MCP tab: ←→ tabs, ↑↓ select server/tool, Space on/off, Enter read-only details, `d` discover a server's tools, `a` add, Esc close. Browsing uses cached metadata and starts nothing. Discovery of a project server first shows the exact command/argv or URL; typed y approves that entry, n/Esc denies, Space pages long entries. Approval is remembered by a hash including configured values; edits ask again. OAuth/login-based servers show `needs login, not supported yet` and are skipped.

Enabled server/tool names and descriptions capped at 240 characters enter the prompt; full schemas load only when selected through `mcp_tools`. The model uses `mcp_call` after selection. Each call shows server, tool, folder and arguments and waits for y/n, including in Don't ask. Typed `a` allows that exact configuration/tool for the session only. No permanent tool permission exists. The popup total and agent banner estimate metadata tokens/request; schemas and results add tokens only on use. Turning a server/tool off clears previously loaded conversation content on the next turn. Model requests still count toward the parent's existing budgets and caps.

Servers run in the daemon and start on selection. Stdio uses `spawn(command, args)` without a shell, cwd set to the agent folder, a fixed minimal base env and only its configured values. It receives no inherited provider key or AI Term variable. This is a trusted third-party program, with the same host access as other commands; the folder is its cwd, not an OS sandbox. HTTP uses only the exact configured URL, refuses redirects, and allows HTTPS or local HTTP. Errors are fixed lines; server stderr never reaches the terminal.

All configured env/header values are treated as secrets and stored in AI Term's Keychain namespace `mcp:<server-id>:<name>`, bound to the approved hash. Settings, responses, transcripts and logs contain no values; views expose at most the last four characters (short values have no suffix). As with the existing key-add form, masked user input travels inward once over the authenticated local socket to the daemon; it is never returned or sent to the model. A project's existing values are read only from its approved bounded `.mcp.json` entry and copied into the same Keychain namespace. Ctrl+K cancels in-flight calls and kills stdio process groups; agent exit stops its connections. Subagents share their parent's MCP permission session and cancellation.

## Linux details (v0.8.1)
Everything above works on Linux too, with these differences:
- **Daemon socket:** `~/.ai-term/run/daemon.sock`, with the same rules as on macOS (folder 0700, socket 0600, refused if the folder is a link or someone else's). `XDG_RUNTIME_DIR` isn't used.
- **Keys:** kept in the Secret Service (GNOME Keyring, KWallet) through the same library as macOS's Keychain. With no keyring running, or a locked one, key features refuse with `No Secret Service keyring (none running, or it is locked); API keys need one, and AI Term never stores them in a file`. There is no file fallback.
- **Sandboxes:** through [bubblewrap](https://github.com/containers/bubblewrap) (`bwrap`, in `/usr/bin`, `/usr/local/bin` or `/bin`; `sudo apt install bubblewrap`).
  - **Tests (D56):** the system is read-only. Your home, other homes, `/tmp`, `/var/tmp`, `/run`, `/media` and `/mnt` are hidden. Toolchains and the repository's git folder come back read-only, key folders stay hidden, and only the worktree and a temp folder are writable.
  - **Test network:** a test run gets its own network, so only its own 127.0.0.1 works. Your machine's services stay closed even with `l` on, which only matters on macOS.
  - **What a block looks like:** a hidden file reads as missing, so a blocked write or network shows `✗ blocked by sandbox`, and a blocked read shows as a test failure.
  - **Agent bash (D57, B29):** AI Term's agent's bash gets its own process list, so it can't see or attach to your other processes. It can't see `~/.ai-term` (its own worktree excepted), AI Term's sockets, or your session's runtime folder (where the D-Bus session bus would hand out Secret Service keys).
  - **Persistence spots:** read-only. Besides the macOS list, Linux adds `~/.xprofile`, `~/.xsessionrc`, `~/.xinitrc`, `~/.pam_environment`, `~/.gnupg/gpg-agent.conf`, `~/.local/share/systemd/user`, Plasma and window-manager autostart (`~/.config/plasma-workspace/env`, `autostart-scripts`, `i3`, `sway`, `hypr`, `openbox`). `~/.local/bin` and `~/bin` stay writable so the agent can install tools there (your choice); a program it puts there could later run as you.
  - **How:** home, `~/.config` and the like are rebuilt for each command with every entry put back, so a startup file that doesn't exist yet can't be created either. Anything new at those levels vanishes when the command ends, and the agent is told so.
  - **Renames:** every folder between them and a protected file, such as `~/work/proj/.git` or a dotfiles folder behind a `~/.zshrc` link, is pinned so it can't be renamed and swapped out. A repository without `.git/hooks` gets an empty one, made read-only.
  - **Unreadable entries:** an entry of home that can't be read, such as a dead network mount, is left out rather than stopping bash.
  - **Where bubblewrap can't start:** in Ask, bash runs the command you approved as before. In Don't ask it refuses.
  - **Session sockets** in `/tmp` are hidden from agent bash (v0.8 gate): the X11 display, a `dbus-launch` bus, ssh-agent and tmux. So are `~/.dbus`, `~/.Xauthority` and `~/.ICEauthority`.
  - **What stays reachable** (as on macOS, where bash also has the network): the Docker socket, and a D-Bus session bus or X11 display on an abstract socket (dbus-launch and X11 sessions share the network namespace). The Secret Service gives any program of yours a saved key while the keyring is unlocked; on such sessions Don't ask can't keep it out.
  - **Toolchains outside home** on `PATH` (Linuxbrew's `/home/linuxbrew`, NixOS's `/run/current-system`) come back read-only for tests.
  - **Without bubblewrap** (or where it can't start, for example with user namespaces turned off): auto-test asks every time (`tests need you · no sandbox`). AI Term's agent offers Ask only, and the start box and `/mode` show why in one line (`don't ask needs bubblewrap (bwrap), which isn't installed`). The same goes anywhere a sandbox can't start, macOS included.
- **Helpers:** `notify-send`, `xdg-open`, `wl-copy`, `xclip` and `xsel` are run only from `/usr/local/bin`, `/usr/bin` or `/bin`. An agent can write a PATH folder in your home, and AI Term runs these outside any sandbox.
- **AppImage:** the daemon starts from the AppImage file itself, not from the app's temporary mount, so it keeps working after the app quits.
- **Notifications:** through `notify-send` when it is installed, else none (`/settings` says `notifications unavailable: notify-send isn't installed`). Clicking one does nothing on Linux.
- **Clipboard** (`y`, `Y`): `wl-copy` on Wayland, else `xclip` or `xsel`. With none of them, the copy says to install one.
- **`/open`:** `xdg-open`. **This machine:** `/proc/meminfo`, `/proc/net/dev` (containers, bridges and VPN tunnels left out) and `ps` CPU time, measured as the change since the last look.
- **Desktop app:** an AppImage and a .deb from `npm run app:dist` on Linux, unsigned. Each ⌘ key in the desktop key table below is Ctrl+Shift there (Ctrl+Shift+C copies, Ctrl+Shift+T starts an agent, and so on). There's no Hide, no Zoom and no `ai` command install from the app.

## Windows details (v0.8.2)
Everything above works on Windows too, with these differences:
- **AI Term's folder:** `%USERPROFILE%\.ai-term`. On creation `icacls` gives your account full control and removes every other entry. Each daemon start reads the folder and each folder in it back (owner and entries, by SID) and refuses to run unless they are yours alone. An Administrators owner, as an elevated terminal makes, counts as yours.
- **Daemon:** a named pipe, `\\.\pipe\ai-term-<your id>-<random>`, a new random part each start. Its name and a token are written to `run\daemon.pipe` inside that folder.
  - A pipe that already exists, whoever made it, makes the daemon stop rather than share it.
  - Node can't narrow a pipe's own ACL, which lets other accounts open it for reading. So the daemon answers nothing until a client shows the token, which only your account can read.
  - Pipe names can be listed, so the client also checks the daemon: the daemon must answer a fresh nonce with proof of the token before anything else is sent. If it can't, the pipe file is removed and `ai` says so.
  - `ai daemon stop` asks the daemon to stop, so it removes its pipe file. The file also goes whenever a stale lock shows the daemon is gone.
  - A daemon may take a few seconds to start (it checks the ACL first). The client waits up to 20 s, and a second start doesn't take over one that is still starting.
- **Keys:** Windows Credential Manager. If it can't be used, key features refuse with `Windows Credential Manager unavailable`.
- **No sandbox:** auto-test asks every time (`tests need you · no sandbox`). AI Term's agent is Ask only: `ask · don't ask needs a sandbox, and Windows has none AI Term can use`.
- **Claude Code and Codex:** a native `.exe` runs directly. npm's `.cmd` launcher is never run: AI Term reads the script (or native `.exe`) it names and starts that with `node` (or directly), the arguments still an array. cmd.exe would read `%`, `&` and quotes in a first message as commands. A `.cmd` that isn't npm's, and any `.bat`, is refused, and so is a launcher that can't be read.
  - `npm test` in `/test` and `npx` MCP servers work the same way (npm's own `npm.cmd`, `npx.cmd`).
  - A first message that starts and ends with `"` and contains a space reaches the CLI split into words (a node-pty quirk); it stays the message, never options.
  - A test or MCP command that isn't on PATH is refused rather than looked for in the agent's folder, which Windows would search first.
- **Agent bash:** Git for Windows' `bash.exe` (never WSL's). Without Git for Windows, bash says it needs it.
- **git:** Git for Windows' `git.exe`, from Program Files or else PATH. Without it, git features say so; AI Term never runs a bare `git.exe`, which Windows would first look for in the repository's own folder.
- **AI Term's agent** keeps the Windows basics it needs (`SystemRoot`, `TEMP`, `USERPROFILE`, …) and nothing else of your env.
- **Paths:** checks of worktree paths ignore case and slash style, as NTFS does. Device names (`NUL`, `CON`…), alternate data streams (`file:stream`) and network paths (`\\server\share`) are refused.
- **Shell agents:** PowerShell (7 when installed, else Windows PowerShell), started with no arguments.
- **Stopping:** `taskkill /T /F` stops an agent's or a command's whole process tree.
- **Not on Windows yet:** notifications (`/settings` says so), network and per-agent CPU in This machine (CPU and memory show), click-through.
- **Clipboard:** `clip.exe` (sent as UTF-16, so non-ASCII text survives). **`/open`:** Explorer.
- **Paths:** paths with spaces and non-ASCII names work. Worktrees stay under `%USERPROFILE%\.ai-term\worktrees`.
- **Known gaps:**
  - An env file you import from anywhere isn't owner-checked (Windows `stat` has no owner); pick your own.
  - PowerShell's Constrained Language Mode (AppLocker, WDAC) blocks the ACL check, so the daemon won't start there.
- **Desktop app:** an NSIS installer from `npm run app:dist` on Windows. It is unsigned, so SmartScreen warns "Windows protected your PC" on first run (More info → Run anyway). The desktop keys are Ctrl+Shift, as on Linux.

## Live smoke suite (`npm run live`)
`npm test` checks the pieces. `npm run live` builds `ai` and drives the real built `ai` in a real terminal (node-pty), typing keys and reading the screen through a headless mirror, the way you'd use it. It is never part of `npm test`.

| Command | What it does |
|---|---|
| `npm run live` | **Tier 1**, needs nothing of yours: 32 checks, about 2½ minutes (one of them waits for a `/queue` minute) |
| `npm run live -- --with-logins` | Tier 1, then **tier 2** on your own logins (only with this flag) |
| `npm run live -- --only <id,id>` · `--from <id>` · `--keep` | Part of tier 1 while you work on the suite (the start check always runs first); `--keep` keeps a failed run's temp world for a look |
| `npm run live -- --with-logins --github <folder> --issue <n> --pr <n> --key-model <model id>` | Tier 2's defaults changed: the checkout whose GitHub origin `/issue` and `/pr-review` read (default `~/ai-term`, cloned to a temp folder first), the issue and PR numbers (default 1), the keyed model (default `claude-haiku-4-5` or `gpt-5-mini`) |

**Tier 1** runs in a throwaway world: a temp folder with a fake home (a planted fake `~/.ssh/known_hosts`, its own `Downloads`), `AI_TERM_HOME` inside it, temp git repos, a throwaway daemon, and a stub Ollama on 127.0.0.1 for AI Term's agent. PATH offers only node, npm and npx, so no Claude Code, Codex, gh or Tailscale is found; Claude Code is played by a small stand-in script where a check needs one. Notifications are off before the daemon starts. It never reaches the internet, never opens a window (`o` is pressed only on a file AI Term refuses, `/open` only as `/open code` with a stand-in `code`), and never touches `~/.ai-term`, `~/Downloads`, your Keychain or your daemon. The world, its daemon and every agent in it are removed at the end.

It checks: start and the login popup, the version on the homepage, adding Ollama, `/settings`, a shell (⏎ in, a resize reaching it, Ctrl+E home, ⏎ back in), resize, multiline paste, `/model`, AI Term's agent in Ask (its worktree, a permission prompt, the cost line; n denies, y approves an edit, Esc interrupts, Ctrl+K kills a running command, a read outside its folder is refused, `/caps turns` pauses it), `/send` (idle, two pasted lines, a paste inside an agent, refused while asking permission, at a trust prompt, for an exited agent and an unknown name), the Don't ask bash sandbox (D57: AI Term's `settings.json` blocked, no planted secret in env, a second branch), `r` rename, splits (Space, v, Ctrl+\ and clicks moving the focus, Ctrl+E and v again, `/exit` in a pane), the test sandbox (D56: the planted `~/.ssh` file blocked, `l` switching 127.0.0.1 for a test that calls a local server), `/commit y`, `/deck` with `s` and `o`, `/study` paged with Space, `/dev` (and two agents' `/dev` on one free port: the second is refused), `/brain`, `/queue` at a time and after an agent, `/find`, `/open code`, `/retry`, `/bisect` on a Node repository whose runner writes into `node_modules`, `x` on worktrees (k, d, the typed branch name), `/clean` and `/worktrees`, `ai doctor` and the `/doctor` popup, and `/exit` (a new `ai` still sees the agents).

**Tier 2** (`--with-logins`) keeps a temp AI Term folder but runs with your real home and PATH, so Claude Code, Codex and gh find their own logins (AI Term never reads them). Claude Code and Codex each get one tiny prompt in Ask and must show a permission prompt, which the suite approves with the phone remote's own keys (1 for Claude Code, y for Codex) after checking the card says it asks. Tier 2 needs you at the terminal: it refuses to start piped or in the background. Then a keyed AI Term agent turn with its cost line, `/issue <n>` (the popup only) and `/pr-review <n>` (y: a read-only review on Claude Code). Your API key is typed by you: the suite hands the terminal to you for the login popup (and for any CLI prompt it doesn't know), then takes over again by itself, or when you press Ctrl+]. The key goes to your Keychain only and is removed when the run ends. Claude Code and Codex keep their own history and folder trust for the temp folder, as they always do.

Each check prints one line. The first failure stops the run with a plain line, what to look at, and the screen at that moment (anything shaped like a key cut out). Ctrl+C stops it cleanly: the world, its daemon and its agents are removed (in tier 2, your key first). An unknown flag or check id stops it before anything starts.

`npm run live` rebuilds `dist/` first: stop an `ai` daemon you run from this checkout's `dist/` (`npm link`) before it, or that daemon may fail to load its next module mid-run. The Mac app's own daemon isn't affected.

Tier 2 answers only Claude Code's folder trust for its own temp folder, and only plain yes/no prompts for exactly the file it asked for (Claude Code: "Do you want to create live.txt?"; Codex: one command naming its path, nothing chained), at most twice per agent. Anything else is handed to you.
