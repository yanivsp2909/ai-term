# v0.1 TUI renderer

Choose the minimal cell renderer for D26. Ink crosses the requested 15% CPU threshold and its input-latency p95 crosses 16 ms in this workload. This is a prototype result, not a claim that every Ink application is slow; it includes rebuilding the same cell screen into React rows/runs. Manual terminal perception remains needs Yaniv.

## Measurements

macOS 26.5.1 arm64, Node 26.3.0; package-lock.json pins Ink 8.0.0, React 19.3.0, node-pty 1.1.0, @xterm/headless 6.0.0. Terminal size 130×45, preview 87×27. Each final run lasted 30 s with live noise and synthetic typing every 400 ms. The runs were serial. Earlier smoke/pilot runs were used to correct preview pacing and evidence capture; only final results-*-30s.json are used here. Ordinary macOS background activity was not disabled.

CPU is the arithmetic average/max of 29 samples using `/bin/ps -o %cpu= -p <prototype pid>` every second after readiness. macOS ps is a smoothed CPU observation, not a perf-event measure of each exact second; it includes startup history in the first samples. It measures the prototype and its in-process xterm parsing, excluding the separate generated-noise child and benchmark parent. Max captures startup and exceeds 15% even for the grid; its sustained average is below the gate but has modest headroom.

Bytes are counted at process.stdout.write before terminal output, excluding initial mode-entry writes and stderr metrics. Thirty one-second buckets exclude the initial screen; average is their arithmetic mean. Overall bytes/elapsed including the initial screen and teardown are also in raw JSON (Ink 22,547 B/s; grid 4,218 B/s). Node write completion / Ink waitUntilRenderFlush define the end timestamp; this measures bytes delivered to the PTY, not pixels painted by Terminal.app. The benchmark continuously drains the outer PTY; real terminal rendering cost is a manual check.

Frame timing starts before makeScreen and includes cell extraction, React conversion/reconciliation (Ink), diff (grid) and awaited write. The first frame/import is included in frame averages; startup is also reported separately from parent Popen to AITERM_READY. Input timing starts in the stdin callback and ends after the frame with that input has flushed. Input is rendered immediately; preview cells are cached until the next 1/30-second deadline, so input frames can exceed 30/s without speeding up the preview.

Exact commands:

```sh
python3 spikes/renderer/measure.py grid --seconds 30
python3 spikes/renderer/measure.py ink --seconds 30
python3 spikes/renderer/measure.py grid --seconds 3
python3 spikes/renderer/measure.py ink --seconds 3
python3 spikes/renderer/measure.py grid --seconds 3 --crash
python3 spikes/renderer/measure.py ink --seconds 3 --crash
```

The harness uses Python pty.openpty, sets the size with TIOCSWINSZ, and starts `/opt/homebrew/bin/node spikes/renderer/main.js <engine>` with argv and a literal minimal environment. It records ps samples, injects generated input, drains output, and imposes a watchdog. The prototypes spawn process.execPath + noise.js through node-pty with a literal minimal env; noise emits only generated text and design-token colors every 30 ms. No AI CLI or model request is involved. Full raw numeric samples and restoration booleans are in spikes/renderer/results-*.json.

## Prototype design and awkward parts

Both use the same theme, cell composition and PTY mirror: status counts, five three-line cards with two-row logo badges, selected accent bar, real preview, fake usage/Mac numbers, and editable command bar. Truecolor originates in docs/design/tokens.json through theme.js. Mirror RGB, palette/default colors, inverse and bold are mapped into cells; no PTY raw output reaches stdout. Preview contains a moving generated line, cursor movement, status-row redraw, CJK double-width and combining accents.

Ink uses Box/Text React rows, grouping cells into foreground/background/bold runs, with incrementalRendering=true. It is genuinely rendered/diffed by Ink; the shared grid only gives both adapters identical screen content. The prototype owns alt screen/raw-mode cleanup; Ink 8 also has an alternateScreen option, but using a shared lifecycle made restoration comparable. The hot path was awkward: xterm cell styles become many React Text nodes, wide cells need skipping rather than ordinary strings, and every update reconstructs rows. Ink handles ANSI incremental line output and reconciliation, but exact terminal-cell layout already requires width bookkeeping, reducing its layout benefit for this homepage. For this spike no native Flexbox card layout was attempted; that alternative could improve component reuse but would need a new measured comparison.

The grid adapter uses absolute cursor addressing, a previous-cell comparison, style runs, and synchronized-output `ESC[?2026h` / `ESC[?2026l`. It writes only changed cells after initial/full redraw. Its adapter is small; most work is common scene composition. Borders and panel sizes are explicit cell arithmetic. The prototype handles mirror wide cells and combining marks, but command-input grapheme width is an approximation: emoji/ZWJ, full wcwidth tables, complete palette fidelity, underline/italic, and cursor editing need a later specified implementation. These prototypes are throwaway, not production TUI code. Small terminals show a compact resize notice and command input; at under 24 rows five full cards cannot fit.

Physical line counts (blank lines included): common main.js 123, screen.js 94, theme.js 28, noise.js 14, input.js 19; grid.js 20; ink.js 11. Thus grid = 298 lines, Ink = 289 lines including shared code; the measuring Python harness is 143 lines and not counted as either renderer. These counts are dominated by the common screen/lifecycle, not the adapters. Build/lint excludes spikes/, and no product UI has been moved into src/.

## Verification observed

- Both 30-second runs exited 0; stdout canonical mode restored, cursor-show, sync-end and alternate-screen-off sequences observed at exit.
- Three-second smoke runs changed the outer terminal from 130×45 to 100×35 and sent SIGWINCH. Both resized the child/mirror, redrew, and exited 0; restoration checks passed.
- `--crash` throws an intentional uncaught error after 1.2 s. Both exited 1 with `intentional renderer crash`; termios ICANON was restored and all three restoration escape checks passed. Teardown runs before the diagnostic is printed. SIGKILL/OS power loss cannot run a JavaScript cleanup handler; “always restored” here covers caught crashes, Ctrl+C and SIGTERM.
- Captured output was fed into @xterm/headless before teardown to inspect the actual rendered screen: five cards, both lower panels, typed command, real generated status and CJK/combining lines occupy matching positions. This verifies screen bytes/cells, not human-perceived flicker or terminal font appearance.

## Palette variants

Added 2026-10-11 after the committed v0.1.4 handover (`2d07284`). This is a renderer-spike comparison, not a roadmap step or product UI change. Only `spikes/renderer/` and this report changed; no dependencies or npm commands were needed.

`node spikes/renderer/main.js grid --palette ink|graphite|slate|auto` selects a palette; the grid default is **auto**. The Ink prototype retains its existing ink palette.

- **ink:** the original dark design-token colors.
- **graphite:** neutral charcoal ground/panels (`#1E1F22`, `#26282C`, `#313338`), brighter gray text, turquoise accent.
- **slate:** blue-gray ground/panels (`#1B2029`, `#232935`, `#2D3443`), brighter gray text, turquoise accent.
- **auto:** ground cells always use SGR 49, the terminal's default background, so there is no painted background box even when detection fails. In raw mode at startup, query OSC 11 and wait at most 200 ms. Parse 2- or 4-digit RGB channels across fragmented reads; consume replies before command input, including late replies. Derive surface/surface-2/line by mixing the detected background 5%/11%/24% toward white, or toward black when relative luminance exceeds 0.5. Dark text/accent/status colors come from slate; the light branch uses the light design tokens. Dark ink-3 is lightened until it reaches 4.5:1 against surface-2. With no reply, use slate's panel/text colors while keeping the terminal-default ground and recording the timeout reason.

**Contrast limit:** the requested dark/light threshold and fixed panel steps make 4.5:1 impossible on some medium-gray backgrounds. For example, `#888888` derives surface-2 `#959595`, where even white reaches only about 3.00:1. Auto caps ink-3 at white and explains this in its exit diagnostic; it preserves the requested panel steps and luminance threshold. Typical dark backgrounds pass; this is not a universal contrast guarantee.
