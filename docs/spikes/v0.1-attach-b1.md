# B1: attach return diagnostics and Terminal.app reproduction

Date: 2026-10-11. Implementation: `af4d7df`.

## Status and root causes

**Current attach/home behavior confirmed working by Yaniv in Terminal.app.** After the fresh-session instructions, Yaniv reported "now works good" and supplied repeated `ai debug attach "$aiterm_session_id"` runs returning with `back in your shell (home key)`. The original unexplained immediate return has not been conclusively explained; the successful manual retest does not establish its historical root cause.

The latest user transcript does explain the reported vim behavior: `back in your shell (home key)` precedes `vim`, so that vim was launched in the calling Mac shell, where AI Term cannot intercept Ctrl+E. The corresponding opt-in AI Term log records `accepted=true inputHex=05`: successful attach followed by a raw Ctrl+E, with no preceding terminal reply or vim command captured. This does not identify who generated that byte or establish the cause of the original undiagnosed return.

A separate, confirmed startup bug appeared twice during full-suite verification: `Server.listen()` created the socket with mode 0700 under umask 0077, before asynchronous chmod changed it to 0600. A fast `Connection.connect()` could observe the intermediate mode and throw `Unsafe daemon socket`. The daemon now creates the socket at 0600 during synchronous binding, restoring the previous umask immediately in `finally`; the later chmod remains. This race explains that connection error, not the user's logged home-key return.

## Changes

- `attach()` returns an explicit reason. `AttachError` carries reasons for failures, and `ai debug attach` prints `back in your shell (<reason>)` on normal completion and failure.
- Reasons cover home key, session exited, daemon gone, attach rejected, stdin not a TTY, error, attached elsewhere, and client interrupted. Numeric exit notices remain validated before printing.
- `AI_TERM_DEBUG=1` enables logging of the reason, whether the response was accepted, and at most the first 64 stdin bytes encoded as hexadecimal. Logging is off by default. Neither stdin text nor env contents are logged. Pre-attach failures have an empty capture.
- Explicit valid negative daemon responses use `DaemonRequestError`. Timeouts and malformed responses remain general errors. Malformed matching responses fail pending requests and close the connection.
- An early exit event followed by a rejected attach can no longer silently suppress the rejection and return as success.
- Failed-connection diagnostics write only after private directories have passed validation. A logging failure is surfaced separately and does not replace the original connection error.
- No input-filter change was justified: realistic startup noise did not trigger it, and Ctrl+E inside an attached real vim was intercepted correctly.

## Needs Yaniv: commands and what each proves

The linked `ai` uses this repository's built CLI, so no new npm link is needed here. Session IDs identify sessions; they are not keys.

1. **Create and enter a fresh session in one copy/paste; then run `ls` inside.** This distinguishes an attached shell from the outer Mac shell and checks normal input/output.
   ```sh
   cd ~/ai-term
   aiterm_session_id=$(ai debug shell ~)
   AI_TERM_DEBUG=1 ai debug attach "$aiterm_session_id"
   ```
   The variable survives in that Mac shell for later reattaches. If attach immediately returns, paste its reason; do not launch vim after the return and assume it is inside AI Term.
2. **Updating program persists:** inside the attached shell, run `top`, press Ctrl+E, then in the Mac shell run `ai debug attach "$aiterm_session_id"`. Top should still be running. Press `q` to quit top, then Ctrl+E. This checks live-output detach and continuity.
3. **Vim persists and resize restores cleanly:** run `ai debug attach "$aiterm_session_id"`. Inside that screen run `vim`, press `i`, type text, resize, then hold Control and press E. In the Mac shell run `ai debug attach "$aiterm_session_id"` again. Text should remain. Press Escape, enter `:qa!`, then press Ctrl+E at the session shell prompt. This checks home from an actual attached editor, snapshot replay and terminal modes.
4. **Exit is explicit:** run `ai debug attach "$aiterm_session_id"`; inside type `exit`. Expect `[session exited with code 0]` and `back in your shell (session exited)`.
5. **Shutdown, when done with every AI Term session:** `ai daemon stop && ls ~/.ai-term/run`. Expect `Daemon stopped.` and no directory entries. This stops all AI Term sessions, so the implementation agent did not run it against the user's current daemon.

If an attach fails, run `AI_TERM_DEBUG=1 ai debug attach "$aiterm_session_id"` and send its printed reason. ## Architecture corrections

No architecture file was changed in B1. Add the distinction between typed daemon rejection and transport/protocol errors to the client error contract. Document that socket mode must be 0600 at creation, not merely after chmod, to avoid the startup observation race. Opt-in bounded hex input diagnostics are an explicit B1 debugging exception to the usual no-input-logging rule; they remain off by default and should not be left enabled for sensitive sessions.
