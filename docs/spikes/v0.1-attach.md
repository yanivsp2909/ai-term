AI Term is the `ai` client plus a private background daemon that owns persistent agent PTYs. This step adds entry into an existing internal shell session and returns to the caller on Ctrl+E. The daemon and shell continue when the client detaches. No homepage, Claude/Codex spawning, key handling or dependency changes were added; the default `ai` command remains the placeholder.

## What changed

- `src/shared/protocol.ts` and `validate.ts`: attach/detach/resize requests, size and UUID validation, terminal-mode response data, takeover events, validated exit codes. Hello now uses the already approved `daemonPid` field.
- `src/daemon/server.ts`: one owner per session, takeover notification, owner-only input and resize, disconnect cleanup, owner removal when a session is removed. Rejected input is logged without its contents.
- `src/daemon/session-manager.ts`: serialized snapshot/ownership transitions, attached size versus detached preview size, independent mirror and attached-client pause reasons. Input remains bytes, including split UTF-8.
- `src/daemon/mirror.ts`: query replies stop while attached and resume after detach; public xterm modes plus parser-tracked mouse encoding and cursor visibility describe the snapshot's terminal state.
- `src/client/attach.ts`: alternate screen, raw input, snapshot then mode restoration and live output; SIGWINCH resize; local restoration before awaiting detach. Output from other session IDs or after detach is ignored. Slow stdout pauses client socket reads, allowing daemon-side attached flow control.
- `src/client/input-filter.ts`: streaming Ctrl+E recognition for byte `0x05`, kitty CSI-u including press/repeat/release variants, and modifyOtherKeys. Bracketed-paste markers survive split reads; pasted Ctrl+E is preserved as text.
- `src/client/terminal-modes.ts`: restore saved input modes on entry and reset mouse, paste, focus, cursor/keypad, kitty/modifyOtherKeys, colors and related screen modes on return.
- `ai debug attach <UUID>`: returns with `back in your shell` on home or session exit. Exit also prints the numeric plain-text status line. Connection failure or an uncaught error restores the terminal and reports an error.

## Needs Yaniv: physical-terminal checks

The UUID is a session ID, not a credential. Keep it for these checks; `debug ls` can recover it later. Replace `<id>` below with the UUID printed by `debug shell`. This creates an internal shell only and does not spend Claude/Codex usage.

1. **Normal shell input/output:**
   ```sh
   cd ~/ai-term
   npm run build && node dist/cli/index.js debug shell ~
   node dist/cli/index.js debug attach <id>
   ```
   Inside the attached shell, type `ls` and press Enter. It should behave like your normal terminal. This checks real keystrokes, prompt, output and full-screen entry.
2. **Vim resize and clean home return:** inside that same attached shell run `vim`, press `i`, type a few characters, resize the window, then press Ctrl+E. You should see `back in your shell`; mouse, keys, cursor and your original screen should behave normally. This checks full-screen modes, resize and detach without stopping vim.
3. **Vim survives detach:**
   ```sh
   node dist/cli/index.js debug attach <id>
   ```
   Vim should still be present with the text you left. Press Escape, type `:q!`, press Enter, then Ctrl+E. This checks snapshot restoration and process continuity.
4. **Continuous output survives detach:**
   ```sh
   node dist/cli/index.js debug attach <id>
   ```
   Run `top` (or `htop`), press Ctrl+E while it updates, then run the attach command again. It should still be running. Press `q`, then Ctrl+E. This checks live output and continuity under frequent redraws.
5. **Session exit returns cleanly:**
   ```sh
   node dist/cli/index.js debug attach <id>
   ```
   Type `exit` and press Enter. Expect `[session exited with code 0]` and `back in your shell`. This checks lifecycle notification and cleanup on process exit.
6. **Daemon shutdown:**
   ```sh
   node dist/cli/index.js daemon stop
   ls ~/.ai-term/run
   ```
   Expect `Daemon stopped.` and no run-directory entries. This stops AI Term's sessions and confirms private socket/PID cleanup.

## Corrections for the planning chat

`docs/architecture.md` was not edited after its initial planning commit. The implementation shows these additions/clarifications are needed:

1. **§4 attach response:** add `sessionId`, `modes` and the current `session` alongside snapshot/cols/rows. The current lifecycle record lets the client handle an already exited session, and mode data restores input/visibility state before streaming.
2. **§4 events and §6 takeover:** document `session.detached {sessionId, reason: "attached elsewhere"}` and one attached owner per session. Only that owner's input/resize is accepted; a former owner's detach is harmless.
3. **§6 entry:** after the snapshot, restore terminal input modes. xterm's public `terminal.modes` covers application cursor/keypad, bracketed paste, mouse tracking and focus; it does not expose mouse encoding or cursor visibility. The mirror tracks those two through its parser rather than reading xterm private internals.
4. **§6 home key:** byte `0x05` alone is insufficient. Include kitty CSI-u/event variants and modifyOtherKeys, streaming sequence parsing and the bracketed-paste exception. A standalone Escape is forwarded after 30 ms while retaining parser context; if the rest arrives later, the recognized Ctrl+E suffix is withheld, although the ambiguous leading Escape may already have been delivered. Ctrl+E inside a bracketed paste is pasted data, not navigation.
5. **§6 leave/exit/error:** explicitly reset terminal modes and restore locally on home, takeover, exit, daemon disconnect, startup Ctrl+C and uncaught errors before waiting for detach. Ctrl+C after attach is input to the agent. The v0.1.4 debug caller returns to the shell; the homepage remains v0.1.5.
6. **§5 flow control:** a slow attached client's stdout must pause its socket reads so the server's socket buffer can apply the documented watermarks. Mirror and attached-client pause reasons must be combined so one draining queue cannot resume a PTY still blocked by the other.

Compatibility gotcha: v0.1.3 code called the hello field `pid`; the approved planning change calls it `daemonPid`. This step aligns code with the document. An already running old daemon must be stopped with its matching old CLI before the rebuild; new clients validate the new hello shape.
