## 7. Codex + Microsoft Foundry

## 8. Usage sources

**from docs:** [Claude monitoring](https://code.claude.com/docs/en/monitoring-usage) supports:

```text
CLAUDE_CODE_ENABLE_TELEMETRY=1
OTEL_METRICS_EXPORTER=otlp
OTEL_LOGS_EXPORTER=none
OTEL_EXPORTER_OTLP_PROTOCOL=http/json
OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:<port>
OTEL_EXPORTER_OTLP_METRICS_ENDPOINT=http://127.0.0.1:<port>/v1/metrics
OTEL_METRIC_EXPORT_INTERVAL=10000
OTEL_EXPORTER_OTLP_METRICS_HEADERS=x-ai-term-session=<per-session receiver credential>
OTEL_METRICS_INCLUDE_SESSION_ID=true
```

Metric names: `claude_code.token.usage` (type input/output/cacheRead/cacheCreation) and `claude_code.cost.usage` (USD), with model/session attributes. CLI cost is an estimate, not a billing ledger. Prefer this metrics-only pipeline for Claude session tokens/cost: cumulative/delta handling and restart deduplication must be specified before implementation. Keep logs/traces and content export disabled. Per-session credentials are runtime-only; never put them in notes or argv. Managed settings may override endpoint choices.

**from docs:** [Claude statusline](https://code.claude.com/docs/en/statusline) receives JSON on stdin including `cost.total_cost_usd`, `context_window.context_window_size`, `used_percentage`, `remaining_percentage`, `current_usage` (input/output/cache counts), and `total_input_tokens`/`total_output_tokens`. Current docs explicitly say those token totals describe the latest context, not session lifetime. Cost resets at `/clear` and is estimated; don't sum statusline context totals as usage.

**from docs:** Codex [advanced config](https://developers.openai.com/codex/config-advanced/) lists `codex.sse_event` with token counts on `response.completed`, plus `codex.api_request` and tool/prompt events. Configure a local OTLP/HTTP logs exporter without changing user config:

```sh
-c 'otel.environment="ai-term"' -c 'otel.log_user_prompt=false' -c 'otel.exporter={otlp-http={endpoint="http://127.0.0.1:<port>/v1/logs",protocol="json",headers={"x-ai-term-session"="<runtime-only receiver credential>"}}}'
```

Recommendation: Codex completed-response OTel events for token usage, estimated deployment-price cost. Validate exact numeric field names, attribution, retries and aggregation from a real run before writing the receiver; the docs confirm counts, not a stable full schema. Unlike Claude's metrics, this channel includes other event kinds (tool output snippets may carry sensitive text even with prompt logging off). Accept only the usage fields and never persist entire event bodies.

**Correction to §9/S12:** OTLP protobuf is not JSON; explicit HTTP JSON avoids that media-type mismatch, but collector exporters may expect OTLP response semantics. Verify their behavior with S12's empty 204, auth/Host/Origin checks and payload cap; 64 KB may be too small for batched logs/metrics. No receiver or model-usage export was tested here. These live checks are **needs Yaniv** and later receiver integration work.
