## Contract and implementation

Frames count the type byte plus payload in their uint32 BE length; the four-byte prefix is excluded. Maximum is 4 MiB. Streaming decoding handles split/coalesced reads with one bounded allocation per frame, rejects malformed UTF-8/JSON, unknown types and invalid data-frame UUIDs. Each connection has a bounded control queue (128 requests, 8 MiB payload budget), and a rejected/malformed connection never executes later coalesced requests.

Request `id` is the correlation UUID; `sessionId` is the target UUID. The eight supported kinds are hello, sessions.list/create/preview/stop/remove/rename and layout.previewSize. Only internal `shell` creates are accepted. There are no attach, key, usage or settings stubs. Successful hello includes protocol, version and the daemon PID; `daemon stop` compares that PID with its private NOFOLLOW lock before signaling it. Success responses are runtime validated in the client.

A preview response contains snapshot, sessionId and its captured cols/rows. Catchup reuses the preview request ID for another snapshot response; Connection emits it as an event when that original request is already complete. No additional event kind was invented. Snapshot publication and dimensions are captured synchronously at the output-queue boundary. A preview subscriber over 1 MiB stops receiving live backlog and gets a fresh snapshot on drain; it never pauses the PTY. Separately, the mirror's own pending-output queue pauses its PTY at 1 MiB and resumes below 256 KiB, protecting the daemon from a fast child.

The mirror retains 5000 scrollback lines. Serialization trims scrollback if JSON escaping would exceed the frame limit. An exceptionally styled **current screen alone** over that limit returns an operation error and cancels the preview instead of emitting an oversized frame; chunked snapshots are a future contract decision.

Files are private, state writes use exclusive same-directory temporary files, fsync, rename and directory fsync. Restart records are always exited with `background service restarted`; persisted PIDs are never killed or resumed. Live shell children use argv arrays and only the always env rules; no env is persisted/logged. Terminal query replies come from the mirror only while detached. Stop signals the PTY process group, TERM then KILL after three seconds. Shutdown attempts socket and session cleanup independently, and safely handles logging/lock cleanup failures.

## Architecture corrections for planning chat

Do not silently treat these as product features from later steps. Architecture was not further edited after the initial planning commit.

1. §1 install gotcha is factually wrong for node-pty 1.1.0: its postinstall does not make spawn-helper executable, and script approval alone does not fix its 0644 published helper. This step pins 1.2.0-beta.15, whose packaged helper is executable, and approves that exact version; no chmod.
2. §4 overloads `id` for request correlation and target session. Use `id` for correlation and `sessionId` for targeting/removal events.
3. §4 should define snapshot response dimensions, catchup responses reusing the preview correlation ID, and hello's daemon PID used for explicit stop. Length includes type plus payload, not the prefix.
4. §5 flow control must separate attached-client flow (later) from preview subscribers: preview never pauses a PTY. Mirror queue backpressure is independent and necessary even with no client.
5. §5 snapshot policy must account for the 4 MiB frame limit: scrollback can be trimmed; an exceptionally styled current screen needs a chunked snapshot contract or a documented error. Unbounded serialize() cannot always fit at allowed sizes.
6. §2's ten-minute rule is explicitly **zero live sessions**, matching implementation; exited records do not keep the daemon alive.
7. §2 logs retain three total files (daemon.log plus .1 and .2), interpreting “3 files kept” literally.
8. Existing PROGRESS checkpoint said D26 Proposed/no daemon and node-pty manual chmod; the new handover supersedes those statements. Provider/auth and rendering manual checks from prior spikes still remain manual.
