# v0.4 plan: AI Term's own agent

Written 2026-10-14 at the start of v0.4.1 (main `56f1755`). Short on purpose; architecture.md §12.5 holds what was built.

## v0.4.1 (this step): one real task, one provider

**Process model.** The agent is a CLI like the others: `ai agent`, spawned by the daemon in a PTY (`process.execPath` + the AI Term entry; source mode adds the tsx loader and pins AI Term's tsconfig, as the status commands do). The homepage, mirror, preview, bar, splits, /send, /find and notifications work unchanged because they only see a PTY. The daemon never talks to the model; the key never enters the protocol, the client, a file or a log.
- `env.ts` builds the agent's env: an allowlist (PATH, HOME, USER, LOGNAME, SHELL, TMPDIR, LANG/LC_*, TERM…) plus `AITERM_AGENT_KEY` and `AITERM_AGENT_ENDPOINT` from the Keychain entry and its B12 binding, the status and usage credentials. The agent copies the key and endpoint and deletes both from its own `process.env` before anything else runs.
- argv (built in `env.ts`): `agent --model=<deployment> --models=<bound ready deployments> --theme=<name> --transcript=<path> --ask|--dont-ask [-- <first message>]`. The Don't ask flag exists only in `env.ts` (the agent imports the constant).

**Provider.** Foundry through `@ai-sdk/azure` (Responses API), because Yaniv's key on record is a Foundry key (narvis-resource, GPT deployments that already passed the Responses test) and the provider sends the key only in the `api-key` header, like the existing Foundry test (S16). The base URL is the bound endpoint (`…/openai/v1`, used as-is by the provider). A custom fetch refuses any URL outside that endpoint and never follows redirects. `provider.ts` is just that one function; v0.4.2 adds the rest.

**Tools** (`src/agent/tools.ts`, `jail.ts`, `bash.ts`): read, write, edit, bash, search.
- File tools resolve every path inside the folder: relative or absolute, then realpath of the target (or its nearest existing parent for a new file) must stay inside realpath(folder); `..`, absolute paths elsewhere and symlink escapes are refused. Writes open with `O_NOFOLLOW`. Size caps on read and write.
- search: `rg` from PATH if present (argv, `--` before the pattern and path), else a plain Node walk (skips `.git`, caps files and matches).
- bash: `execFile('/bin/sh', ['-c', command])` in the folder, its own process group, a timeout (kill the group), a 64 KiB per-stream output cap, and an env from `buildBashEnv` in `env.ts`: an allowlist with no API keys, nothing AI Term set (`AITERM_*`, `AI_TERM_*`, OTEL), nothing matching KEY/TOKEN/SECRET/PASSWORD. Output and transcript lines replace the session key with `[redacted]`.
- bash is not sandboxed (it runs as you, like Claude Code's bash); Ask is the guard. A Seatbelt write jail is a later candidate.

**Permissions.** Ask by default: every write, edit and bash shows exactly what will run (the command, or the path and a diff) and waits for one `y`/`n` keypress outside a paste. Before the prompt is drawn the agent reports `waiting: permission` and waits for the daemon's 204, so /send can never answer it (no late-hook window). Don't ask is per session only (a red `!`), never a saved default; reads and search never ask.

**UI** (`src/agent/ui.ts`): a scrolling transcript in the normal screen, so the mirror, preview and /find read it as text. `› ` prompt line with bracketed paste; streamed replies; tool calls as one dim row each (`· read src/a.ts`, then `✓`/`✗` with a short result); Esc interrupts a turn (AbortController), Ctrl+C twice quits; a message typed during a turn is queued. Colors from `tokens.json` through `theme.ts`; nothing animates. In-agent commands: `/model [id]` (only the key's bound, tested deployments), `/cd <folder>` (re-reads AGENTS.md), `/help`, `/exit`.

**Instructions.** `AGENTS.md` from the folder, then `CLAUDE.md` with its `@file` imports resolved inside the folder (depth 3, 64 KiB per file, 256 KiB total, each file once), go into the system prompt after a short fixed preamble.

**Transcript.** `<home>/sessions/<id>/transcript.jsonl` (0600, in the 0700 session folder, deleted with the session): one JSON object per line, `{v:1, at, kind:'user'|'assistant'|'tool-call'|'tool-result'|'note', …}` with text capped and the key redacted. Resume reads it from v0.4.2 on; v0.4.1 only writes it.

**Status and usage** (no special cases in cards, notifications, `c`, Usage):
- `POST /v1/status/ai-term` with the session's status credential (a new engine-bound route, 204 always): `{event:'turn-start'|'tool-start'|'tool-finish'|'permission'|'done'|'turn-failed'|'model', tool?, reply?, error?, model?}`. The daemon maps them onto the existing reducer events (running / waiting permission / done + last reply / waiting turn failed), so toolsInFlight and the /send gate work as for Claude.
- `POST /v1/metrics` with the usage credential: OTLP JSON, sum `ai_term.token.usage` delta points typed input / cacheRead / output with a `model` attribute. Priced by the price table (Foundry: override, Azure, OpenAI), so cost is an estimate as for Codex.
- ctx %: the reducer path exists, but no context window is known for a Foundry deployment name, so it stays empty until v0.4.2 brings Models.dev limits.

**Routing (D47).** New setting `keysRunOn: 'ai-term' | 'cli'` (default ai-term; `/settings` r toggles). A key whose provider the agent supports (Foundry in v0.4.1) starts engine `ai-term`; with `cli`, or for Anthropic and OpenAI keys until v0.4.2, keys start the CLIs as before. Account logins always start the official CLIs. The routing function lives in `src/shared/models.ts`, so the model picker shows what the daemon will start; the daemon applies it again on create.

**Protocol first.** `Engine`/`AgentEngine` gain `'ai-term'` (permission ask | dontAsk, no effort); `Settings.keysRunOn`; an `ai-term` request needs key auth. Old records load unchanged. Resume refuses an ai-term agent in v0.4.1 (no transcript reader yet); /retry starts it fresh.

## What later steps build on (proposed)
- **v0.4.2 providers and money:** Anthropic and OpenAI keys, Foundry chat-only deployments, Models.dev limits (ctx %), exact cost from provider usage, the hard budget that stops before a request crosses it, resume from the transcript. The provider layer grows from `provider.ts`; the tool, permission, status and transcript formats stay.
- **v0.4.3 skills, subagents, slash commands (D48):** read-only allowlisted folders under `~/.claude`, `~/.codex`, `~/.agents`, loaded lazily into the system prompt and the in-agent command list.
- **v0.4.4 MCP servers:** AI SDK MCP client, secrets in the Keychain, MCP tools behind the same Ask gate.

## Risks
| Risk | Mitigation |
|---|---|
| A tool path escapes the folder (symlink race) | realpath check plus `O_NOFOLLOW` on the last component; bash is outside the jail by design and always asks in Ask mode |
| The key leaks to bash, the transcript, logs or the protocol | allowlist env for bash; key deleted from the agent's own env at start; redaction of the exact key in tool output and transcript; the daemon only builds env |
| A /send answers an approval | the agent reports waiting and waits for the 204 before drawing; approvals take one keypress outside a paste |
| Status drift if a POST fails | turns still work; the card can lag like a lost hook; failures are counted, not logged with content |
| The real model call can't be tested here | stub-model tests for every path; the real run is a manual check for Yaniv |

## v0.4.3 implementation choices (2026-10-14)

- One D48 reader, invoked by the daemon for the homepage and through the engine-bound agent query route. No other module opens extension paths. Tests supply a temporary home; live folders are not inspected during development.
- Exact roots from the task; project sources win name clashes, then Claude, Codex prompts, shared skills. Duplicate resolved files are read once per kind. Denied path components are case-folded and checked on both logical and resolved paths; targets must stay under home.
- 64 KiB per file, 1 MiB per scan, 500 items, 4,000 visited entries, depth eight, 240 description characters. The token display estimates UTF-8 bytes / three; it measures names/descriptions in the manifest, not loaded bodies or tool schemas. Command rows cost zero until invoked.
- On/off overrides live in AI Term settings by a stable hash of kind and source path. Default on for skills, agents and commands: discovery does no model work. Standalone automatic jobs remain off (D55).
- Tasks run serially as separate conversations, with shared RunLimits, Ask IO, usage reporter, folder and cancellation signal. Exact keyed model IDs match first; familiar Claude aliases may match a uniquely available keyed Claude model. Anything else uses the parent. Tasks cannot recursively spawn tasks.
- A task requires a job confirmation (D49), showing model, token/price range, then its writes and commands still require the parent's Ask approvals. Only its final answer enters the parent conversation; intermediate text stays out of the parent's model context.
- One tabbed popup model/drawing shared by homepage and agent; read-only full-file view scrolls and Esc returns to the list. No animation. Toggles clear the agent's conversation before the next message, so a disabled body's earlier tool result cannot continue costing tokens unnoticed.
