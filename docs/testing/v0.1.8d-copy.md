## Interpretation and limits

- “5 MB” is implemented as 5 MiB (5 × 1,024 × 1,024 UTF-8 bytes), consistent with existing frame/storage caps. A cut may start partway through an oldest logical line but never inside a Unicode code point; the note says oldest lines cut at 5 MB. Newest content retained.
- A 5 MiB text response cannot fit the existing 4 MiB frame limit, especially with JSON escaping. One logical request is returned in bounded control chunks; no global frame-limit increase. Copy responses are not preview bytes/events and never reach the terminal renderer.
- The active terminal buffer is copied: normal screen has retained scrollback; alternate-screen CLIs expose the active alternate screen. Old output is not reconstructed from raw PTY bytes or CLI files. Daemon restart restores records but has empty mirrors, so old terminal content cannot be copied after a restart.
- Failure logs are fixed text through Logger; clipboard exception/body content never enters notes/logs. No copy text is redacted: user-requested rendered AITERMCANARY is intentionally copied. The text is never persisted by AI Term.
- Same-user socket trust is unchanged (D35). The request validates session UUID, then manager checks existence before mirror access; unknown → Session not found. Clipboard remains an explicit user action.
- Tests inject fake copiers/executors; the real macOS clipboard was not touched. A fake vault was not needed for this step. No real CLI sessions/auth, home/keychain/.env reads, network calls or daemon stops. Only explicitly requested final origin push uses network.
