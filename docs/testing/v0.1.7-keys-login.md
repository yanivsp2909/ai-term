## Decisions / limits

- Added only @napi-rs/keyring 2.1.1: platform Node has no cross-platform OS credential API; D24 requires it. Linux explicitly requires Secret Service, preventing silent in-memory fallback.
- OpenAI API key option uses OPENAI_API_KEY plus Codex model_provider=openai; Anthropic/Foundry existing rows retained. Only Anthropic and Foundry real runs requested below.
- Short secrets (≤4 chars) remain valid per request but expose empty last4. Metadata fields cannot contain the supplied complete secret.
- Foundry import requires AZURE_OPENAI_ENDPOINT and AZURE_OPENAI_DEPLOYMENT in the selected source file; scan returns credential names only. Other imports need only the credential assignment. Do not edit a source file to complete import; /login supports explicit Foundry fields.
- Key form clears its field before request serialization; request copy cleared immediately afterward. JavaScript immutable strings cannot be securely zeroed in the runtime, but no client object retains it after send/dispose. Queued/coalesced input is tested.
- Metadata/state contain auth references/views only. Removing key does not stop existing sessions. Failed save removes the new native entry, and failed deletion remains explicit. Metadata/settings writes serialize per path.
- Real daemon never stopped/read. Tests use /tmp homes and native test service only; .claude, spikes, docs/spikes, docs/reviews untouched. No usage/hooks added.
